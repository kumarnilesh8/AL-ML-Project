**Input**: Feature specification from `kitty-specs/doctrine-pack-remediation-georgia-templates-01KWCBN5/spec.md`

## Summary

Remediate integrity, schema, duplication, and clarity debt in the PS doctrine pack
(evidence: `work/reports/2026-06-30-doctrine-squad-synthesis.md`) and extract Gemini Bot
Georgia's generated output structure into a `pack/templates/gemini/` template family.
Approach: treat the pack repository as the system under change — YAML artefacts plus the
DRG-compiler tooling — and decompose the work into independent concerns that can be
validated by the pack's existing gates (`spec-kitty doctrine pack validate`, DRG freshness
hook, MANIFEST integrity).

## Implementation Concern Map

> Concerns are NOT work packages. `/spec-kitty.tasks` translates these into executable WPs.

### IC-01 — Gemini template extraction

- **Purpose**: Capture Georgia's output structure once as `template` artefacts so structure changes happen in one place and the profile stays lean.
- **Relevant requirements**: FR-001, FR-002, FR-003; NFR-004
- **Affected surfaces**: `pack/templates/gemini/*`, `pack/agent_profiles/gemini-bot-georgia.agent.yaml`, `gemini-agents/README.md`
- **Sequencing/depends-on**: independent for the net-new template files; but **must complete before IC-05** for `gemini-bot-georgia.agent.yaml` (IC-05 canonicalizes the *slimmed* profile, not the bloated one).
- **Risks**: must preserve every currently-documented output field; ensure README/profile/templates agree (kill triplication, not content).

### IC-02 — DRG external-node declaration & edge hygiene

- **Purpose**: Declare `doctrine-daphne` and `planner-priti` as external/inherited (built-in) nodes with provenance; remove the self-referencing and duplicate edges; add a machine-readable `external_nodes` section.
- **Relevant requirements**: FR-004 (disposition: external), FR-006
- **Affected surfaces**: `pack/drg/fragment.yaml`
- **Sequencing/depends-on**: precedes IC-03. **⚠ Shares `fragment.yaml` with IC-04a (orphan wiring)** — these two MUST be merged into a single "DRG source cleanup" WP (or strictly serialized) to avoid concurrent edits to the same file. IC-03 then consumes the settled `fragment.yaml`.
- **Risks**: external-node schema must be one the compiler/validator understands (resolved in research R1); fragment.yaml co-edit collision with IC-04a (mitigated by merge).

### IC-03 — DRG compiler correctness

- **Purpose**: Fix `tools/compile-drg.py` so it derives each edge target's kind from local pack artefacts/MANIFEST + declared external nodes, instead of defaulting unresolved targets to `directive:`; regenerate `graph.yaml`.
- **Relevant requirements**: FR-005
- **Affected surfaces**: `tools/compile-drg.py`; regenerated `pack/drg/ps-agent-enabled-factory.graph.yaml`
- **Sequencing/depends-on**: **after the merged IC-02 + IC-04a fragment WP is final** (compiler must read the settled `fragment.yaml` including orphan-node wiring), else `graph.yaml` regenerates stale. **Pre-condition:** run `spec-kitty doctrine fetch --pack regnology-all-company` first (populates `.doctrine-cache/skills/pack`) so genuinely-upstream IDs resolve — this is a setup step, NOT the fix for the local misclassifications.
- **Risks**: **root cause corrected (research R3)** — the defect is local kind-derivation, not a missing upstream fetch. Must derive kind from local pack/MANIFEST; **verify all ≥41 mis-prefixed targets** are fixed (incl. `regnology-main-context` ×11), not just the 2 originally sampled. First task step = reproduce the defect and prove the fix corrects local IDs.

### IC-04 — Pack integrity (MANIFEST + orphans) — **split into two phases**

- **Purpose**: Wire (or remove) the orphan paradigms, then refresh `MANIFEST.yml` for all on-disk artefacts.
- **Relevant requirements**: FR-007, FR-008
- **IC-04a (orphan fragment wiring)** — affects `pack/drg/fragment.yaml` (+ the two orphan paradigm files). **Runs as part of / merged with the IC-02 fragment WP, and BEFORE IC-03** (so the regenerated graph reflects the wired orphans). R5 decision: wire them in by default.
- **IC-04b (MANIFEST refresh — terminal gate)** — affects `pack/META/MANIFEST.yml`. **Runs LAST, after IC-03 has produced the final `graph.yaml` and all other file edits (IC-01/05/06/07) have settled.** Regenerate hashes via the supported tool (research R4), never by hand.
- **Sequencing/depends-on**: IC-04a → IC-03 → (all other edits) → IC-04b.
- **Risks**: if IC-04b runs before files settle the manifest is immediately stale; if IC-04a runs after IC-03 the graph misses the orphan nodes.

### IC-05 — Schema canonicalization (research-gated)

Research R2 (non-breaking) resolved — no DDR needed.
- **Risks**: co-edit collisions on `gemini-bot-georgia` (IC-01), orphan paradigms (IC-04a), and `sqlx-specialist-simon` (IC-06) — all mitigated by the dependencies above.
