03 / 25 — LCEL

LCEL — LangChain Expression Language

A declarative, composable way to build chains using the pipe | operator. Every component is a Runnable.

# The Runnable Protocol — every LCEL component implements:
# .invoke()  .batch()  .stream()  .ainvoke()  .abatch()  .astream()

from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from langchain_core.output_parsers import StrOutputParser

prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a {role} expert."),
    ("human", "{question}"),
])

# Pipe operator composes Runnables into a RunnableSequence
chain = prompt | ChatOpenAI(model="gpt-4o") | StrOutputParser()

result = chain.invoke({"role": "Python", "question": "Explain decorators"})

13 / 25 — RAG

Full RAG Pipeline

Retrieval-Augmented Generation end-to-end using LCEL.

from langchain_core.runnables import RunnablePassthrough
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from langchain_core.output_parsers import StrOutputParser

# 1. Build retriever
retriever = vectorstore.as_retriever(search_kwargs={"k": 5})

# 2. RAG prompt
rag_prompt = ChatPromptTemplate.from_template("""Answer based on context:
Context: {context}
Question: {question}
Answer:""")

# 3. Helper to format documents
def format_docs(docs):
    return "\n\n".join(d.page_content for d in docs)

# 4. Full RAG chain with LCEL
rag_chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | rag_prompt
    | ChatOpenAI(model="gpt-4o")
    | StrOutputParser()
)

answer = rag_chain.invoke("What is LCEL?")

15 / 25 — Tools

Tools & Tool Calling

Give LLMs the ability to interact with external systems via structured tool definitions.

from langchain_core.tools import tool, StructuredTool, BaseTool

# Method 1: @tool decorator (simplest)
@tool
def search_web(query: str) -> str:
    """Search the web for current information."""
    return search_api.search(query)

# Method 2: StructuredTool with Pydantic schema
from pydantic import BaseModel, Field

class CalcInput(BaseModel):
    expression: str = Field(description="Math expression to evaluate")

calc_tool = StructuredTool.from_function(
    func=lambda expression: str(eval(expression)),
    name="calculator",
    description="Evaluate math expressions",
    args_schema=CalcInput,
)

# Bind tools to a model for function calling
llm_with_tools = llm.bind_tools([search_web, calc_tool])
response = llm_with_tools.invoke("What is 2^10 + 42?")
# response.tool_calls → [{"name": "calculator", "args": {"expression": "2**10 + 42"}}]

Agents — Autonomous Reasoning

LLMs that decide which tools to call and in what order to accomplish a goal.

from langchain.agents import create_tool_calling_agent, AgentExecutor

18 / 25 — Callbacks

Callbacks & Observability

Hook into every step of chain execution for logging, monitoring, token counting, and tracing.

from langchain_core.callbacks import BaseCallbackHandler

class TokenCounter(BaseCallbackHandler):
    def __init__(self):
        self.tokens = 0

    def on_llm_new_token(self, token, **kw):
        self.tokens += 1

    def on_llm_end(self, response, **kw):
        print(f"Tokens: {self.tokens}")

    def on_chain_start(self, serialized, inputs, **kw):
        print(f"Chain started")

    def on_tool_start(self, serialized, input_str, **kw):
        print(f"Tool called: {input_str}")

    def on_chain_error(self, error, **kw):
        print(f"Error: {error}")
    
HANDLER

Callback Events

# Pass callbacks at runtime
result = chain.invoke(
    {"input": "Hello"},
    config={"callbacks": [TokenCounter()]}

19 / 25 — Streaming

Streaming Responses

Token-by-token output for real-time UX. LCEL makes every chain streamable automatically.

# Basic streaming
for chunk in chain.stream({"question": "Explain quantum computing"}):
    print(chunk, end="", flush=True)

# Async streaming
async for chunk in chain.astream({"question": "Explain quantum computing"}):
    await websocket.send(chunk)

# astream_events — granular event-level streaming
async for event in chain.astream_events({"question": "query"}, version="v2"):
    kind = event["event"]
    if kind == "on_chat_model_stream":
        print(event["data"]["chunk"].content, end="")
    elif kind == "on_tool_start":
        print(f"\n🔧 Tool: {event['name']}")
    elif kind == "on_retriever_end":
        print(f"\n📄 Retrieved {len(event['data']['output'])} docs")

Advanced Chain Patterns

# 1. PARALLEL EXECUTION — fan-out / fan-in
from langchain_core.runnables import RunnableParallel

parallel_chain = RunnableParallel(
    summary=prompt_summary | llm | StrOutputParser(),

# 2. CONDITIONAL BRANCHING

route = RunnableBranch(
    (lambda x: "code" in x["topic"], code_chain),

22 / 25 — Caching

Caching & Performance

Reduce cost and latency by caching LLM responses at multiple levels.

from langchain_core.globals import set_llm_cache
from langchain_community.cache import (
    InMemoryCache,
    SQLiteCache,
    RedisCache,
    RedisSemanticCache,
    GPTCache,
)

# Exact-match cache (in-memory)
set_llm_cache(InMemoryCache())

# Persistent SQLite cache
set_llm_cache(SQLiteCache(database_path=".langchain.db"))

# Semantic cache — returns cached response for SIMILAR queries
set_llm_cache(RedisSemanticCache(
    redis_url="redis://localhost:6379",
    embedding=embeddings,
    score_threshold=0.95,
))

# Now all LLM calls are automatically cached!
llm.invoke("What is AI?")   # → calls API
llm.invoke("What is AI?")   # → returns cached
llm.invoke("Tell me about artificial intelligence")  # → semantic cache hit!

24 / 25 — Best Practices

Production Best Practices

Battle-tested patterns for building reliable, scalable LangChain applications.

Architecture

Use LCEL over legacy chains. Prefer langchain-{provider} packages. Use LangGraph for complex multi-step flows. Keep chains modular and composable.

RAG Optimization

Tune chunk size (500-1500 chars). Use hybrid search (BM25 + vector). Add re-ranking. Implement metadata filtering. Track retrieval metrics.

Error Handling

Use .with_fallbacks() for LLM redundancy. Set .with_retry() for transient errors. Use OutputFixingParser for self-healing. Implement max_iterations on agents.

Observability

Integrate LangSmith for tracing. Track token usage & latency. Log intermediate steps. Use astream_events for granular visibility.

Cost Control

Enable caching (semantic preferred). Use smaller models for routing. Batch requests when possible. Set token limits. Use streaming for better UX.

Security

Never execute arbitrary code from LLM output. Sanitize tool inputs. Use allow-lists for tool access. Implement rate limiting. Audit agent actions.
