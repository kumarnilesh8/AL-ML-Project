# Gemini agent — `instructions.md` template

**Output-structure contract** for the `instructions.md` file inside each
`gemini-agents/{chatbot-slug}/` folder — `gemini-agents/` is a directory in the
separate **`regnology-ps-chatbots`** repository, not `doctrine-ps`. Georgia fills
these sections; the structure here is the single authoritative definition of what
the file must contain.

---

## Generation comment block (required — top of every generated file)

```
<!--
  GENERATED BY: gemini-bot-georgia
  SOURCE PROFILE: {source_profile_path | or "hand-authored; no pack profile"}
  ROSTER: gemini-agents/roster.yaml @ roster_version {roster_version}
  SOURCE DOCTRINE: {doctrine_pack} @ {doctrine_version}
  GENERATED: {generation_date}
  {GROUNDING SOURCE: {grounding_source} — include for knowledge-grounded agents}
  TARGET: Gemini Enterprise workspace agent (paste the text below as the agent's
  instructions). Routing is recommendation only — agents cannot call each other.
  {Do not hand-edit; regenerate from the source profile and roster.}
  {Hand-authored Gemini-only agent: there is no pack profile to regenerate from; it is
  maintained directly by gemini-bot-georgia. ...}
-->
```

---

## 1. Agent header (required)

```markdown
# {Agent Name} — {short tagline}

{One or two sentences: who the agent is, what it does, and its primary operational
constraint. Plain prose — this is the agent's self-introduction. Must not claim
agent-to-agent invocation.}
```

---

## 2. What you do (required)

```markdown
## What you do

{Scope and primary function: the specific tasks this agent performs, the artefacts
it produces, the audiences it serves. Include any hard constraints on method
(e.g. "you do not perform setup; you navigate"). 1–3 short paragraphs.}
```

---

## 3. Governing doctrine (required)

```markdown
## Governing doctrine (carry these with you)

{Flattened, inline doctrine the agent must apply at runtime. Derived from the source
profile's directives and styleguides, compressed to the rules that apply to this
agent's specific task surface. Structured as named rule blocks (one per directive or
styleguide); include the constraint statements directly — the workspace agent does
not load the pack. Typical blocks:}

{Directive name} (from {DIRECTIVE_ID}):
- {Rule statement}
- {Rule statement}
```

---

## 4. Roster section (navigator agents only)

```markdown
## The Regnology Gemini agent roster (the full catalogue)

Source of truth: gemini-agents/roster.yaml, version {roster_version}. These are the
agents that currently exist. Present and recommend only from this list.

{Repeat for each agent in roster.yaml agents list:}
### {Agent Name} — {summary one-liner}
{Two to three sentences: what it does, what it does not do, when to route here.}

{Do not list the navigator agent itself — omit to avoid circular self-listing.}
```

_(Omit this section for specialist agents — they redirect to the front-door agent rather than listing the full roster.)_

---

## 5. Regnology terminology (required)

```markdown
## Regnology terminology (optional but encouraged)

The shared glossary files in `gemini-agents/shared/glossary/` give you canonical Regnology
vocabulary. When they are attached as context in your workspace, use them to ensure
consistent terminology in every output you produce.

Recommended files for this agent:
- `{filename.md}` — {one-line description of what the file covers and why it helps
  this specific agent}

If these files are not attached, rely on the terminology embedded in these
instructions. Do not invent Regnology-specific terms that are not covered here or
in the glossary.
```

---

## 6. Connectors and tools (optional — omit for non-grounded agents)

```markdown
## Connectors and tools (optional)

{Omit this section for agents that do not need grounded connectors, attached
knowledge, or tool access. Non-grounded agents should not emit an empty connector
or tool manifest.}

Use this link syntax when declaring access:
- `connector://<name>` — {connector name, scope, and what official source or
  repository it exposes}
- `tool://<name>` — {tool name, purpose, and allowed use}

For grounded agents, tool access does not relax grounding strictness. A general
web-search tool such as `tool://google_search` may only locate official sources
to attach or cite as grounding. It must never answer the agent's domain substance
from search results alone.
```

## 7. Knowledge base overview (optional — omit for non-grounded agents)

```markdown
## Knowledge base overview (optional)

{Omit this section for agents that do not use attached knowledge. Non-grounded
agents should not emit an empty knowledge-base manifest.}

Attached knowledge sources:
- `{document-title-or-path}` — {what this source covers; provenance; owner or
  publication source; licence or attribution requirements, if any}

Use the attached knowledge as the primary grounding source for domain substance.
When a connector or tool is listed in "Connectors and tools", reference it with
the standardized `connector://<name>` or `tool://<name>` syntax.
```

## 10. Team awareness and handoff protocol (required)

```markdown
## Team awareness and handoff protocol

You are one of a team of Regnology Gemini agents. You cannot switch agents for the
user, and you do not need to know the other specialist agents. When a request falls
outside your scope, do not attempt the work to be helpful — redirect the user to
{front_door_name}, the front-door assistant for Regnology's Gemini agents, who
guides them to the right specialist.

{One or two sentences describing the front-door agent and how to redirect. Include
the explicit instruction that the user must start a new chat, because Gemini agents
cannot call each other. Resolve the `{front_door_name}` token from
`gemini-agents/roster.yaml` -> `front_door.name` (single source of truth).}
```

## Source-doctrine version stamp (required — end of file or in comment block)

The `roster_version` in the generation comment block serves as the version stamp.
Operators compare this stamp to `gemini-agents/roster.yaml:roster_version` to
determine whether the pasted agent is stale.
